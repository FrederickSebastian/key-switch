# Linux / Windows TUI 接入方案（基于 main v1.1.0）

## 1. 基线与范围

- 2026-10-07 已获取并检查 `upstream/main`，基线为 `78382a6`（应用版本 `1.1.0`）。当前功能分支 HEAD 仍为 `7323334`，实施前先合入最新 main，保留上游功能及测试。
- 新增独立 Rust TUI，首版支持 Windows x64、Linux x64 本地桌面终端。与升级后的桌面端共享业务核心、数据目录和系统密钥库，同一用户只允许运行一个实例。
- 提供供应商与 Key 管理、搜索、供应商顺序调整、检测和复制。Key 列表的展示排序仅影响当前会话，不新增 Key 排序持久化协议。
- 暂不支持 SSH、无桌面 Linux、WSL、图片编辑、自动更新或设置编辑。不新增 macOS TUI 构建及验证任务，保留现有 macOS 桌面配置。

## 2. main 更新带来的约束

- 桌面主页面已改为供应商侧栏与当前供应商 Key 列表；保留 `ProviderNavigation.vue`、`selectedProviderId`、首次选中首项、删除后回退及刷新保留选择的行为。
- 桌面搜索当前仅针对右侧 Key。TUI 的供应商搜索属于自身交互，不改写桌面搜索设计；过滤后的供应商不能作为完整排序请求提交。
- 保留桌面排序保存期间禁用重复提交、失败仅恢复顺序并保留期间元数据修改的逻辑，以及 `Alt + ↑ / ↓` 键盘排序和减少动画支持。
- 设置分类路由为 `/settings/general`、`/settings/data`、`/settings/about`。核心提取不得改变这些页面或设置写入队列。
- `AppSettings` 已包含 `themePreference`，上游本次补齐了文档；该字段并非本次新引入。共享核心保留 `schemaVersion: 1`、`localePreference` 和 `themePreference`，缺字段沿用现有默认值。TUI 首版只使用语言偏好，不写回设置。
- CI / 发布使用 Node.js 22，新增 `npm run test:frontend`。现有 `tests/navigation.test.mjs` 必须作为回归检查保留。
- 网络请求 User-Agent 已使用 `CARGO_PKG_VERSION`。提取核心后确保核心、TUI、桌面版本一致，避免请求头意外采用不同的核心包版本。

## 3. 共享架构

- 新增 `crates/key-switch-core` 和 `crates/key-switch-tui`，TUI 使用 Ratatui + Crossterm。
- 建立根 Cargo workspace，成员包含 `src-tauri` 和两份新 crate，默认成员选核心和 TUI，支持无需 WebView 的独立构建。
- workspace 使用根 `Cargo.lock`；将现有锁定依赖转入统一锁文件，避免顺带升级。同步 CI 缓存、构建命令、忽略规则、版本校验及开发文档中的锁文件位置。
- 从 `src-tauri/src/lib.rs` 提取数据模型、设置读写、业务操作、持久化、凭据访问、检测规则和安全日志。核心不依赖 Tauri、WebView、终端库。
- 桌面端保留现有命令名称、参数、Serde camelCase 字段、返回值和错误码，使用适配层调用核心；更新安装、窗口主题、打开目录等桌面能力留在 Tauri 侧。
- 核心接受明确数据目录、凭据接口及剪贴板接口；测试使用模拟凭据、剪贴板和故障注入，不访问真实用户凭据。
- 保持应用标识符和密钥库 service `com.app.key-switch`、`key-switch-data.json`、`settings.json` 及现有 JSON 字段，无业务数据迁移。
- 桌面以 Tauri `app_data_dir()` 为准，TUI 对照该实现解析 Windows 用户目录和 Linux XDG 目录。加入默认目录、覆盖环境及非 ASCII 路径测试，不能仅凭目录命名推定一致。
- 内置目录的稳定 ID、中英文名称、缩写、颜色和平台 URL 使用共享非图形来源；Vue 保留图片映射。检测规则统一由核心实现，保留现有端点限制、DNS/IP 防护、禁止重定向、超时及响应大小限制。
- 已有供应商名称、备注、图片字段按原样保留。新增内置供应商按当时语言写入名称；不随语言切换重命名。

## 4. 启动互斥

- 核心在应用数据目录打开专用锁文件，并获取操作系统级非阻塞独占锁。不得以文件存在判断运行状态，不删除、截断或替换锁文件。
- 启动仅允许先解析目录、创建目录及获取锁；成功后才能读设置、恢复文件、访问业务数据、凭据或写应用日志。
- 桌面配置当前自动创建窗口，不能只在现有 `setup` 中追加锁。将主窗口改为显式创建，在 setup 获取并托管进程锁后创建窗口，保留现有尺寸、标题和其他窗口行为。
- TUI 在进入原始模式及 alternate screen 前获取锁，锁持有到进程结束。
- 区分已有实例与目录/锁不可用：桌面使用原生提示，TUI 普通输出，随后退出；不得继续初始化业务服务。提示根据系统语言解析，不提前读取设置。
- 正常退出、强制结束或崩溃由操作系统释放锁；遗留文件不阻止重启。
- 锁保证只覆盖接入协议后的版本，发布说明要求升级并关闭旧桌面实例。v1.1.0 现有桌面尚未参与锁协议。

## 5. 单进程事务与数据安全

- 当前业务数据仍直接 `fs::write`，检测持有旧快照跨网络等待，不能将其直接搬入核心而视为已解决安全问题。
- 核心对业务读取/修改和恢复提供统一串行入口，修改流程涵盖重读、校验、凭据操作、保存及失败处理；保持设置锁和日志锁，明确锁顺序。
- 检测在事务内取得目标快照及版本标记，释放事务锁后进行网络请求；完成后重读并只合并仍匹配的 Key 与检测配置。
- 凭据替换、删除、重新创建、检测配置修改以及较新的检测都使旧检测结果失效。版本标记保留在当前进程内，不新增明文或凭据摘要到 JSON。
- 仅更新检测字段，保留检测期间的备注编辑、新增项、删除项和供应商顺序；单 Key 与批量检测的成功、DNS 失败和不支持分支均走同一合并规则。
- 排序请求验证 ID 是当前完整供应商集合的一次排列，拒绝重复、未知及缺失 ID；TUI 搜索模式下禁用移动顺序，或基于完整列表计算顺序。
- 元数据保存采用临时文件、写入同步、备份替换、失败回滚及中断恢复；启动恢复只在获取进程锁后执行，验证候选 JSON 后选择可恢复版本。按平台实现目录同步，并明确其持久性保证。
- Key 创建用随机唯一 ID，保留历史 `id` / `secretId` 解析。凭据写入后元数据失败时删除新凭据；替换失败恢复旧凭据；删除 Key 或供应商失败恢复已经删除的凭据。任何回滚失败返回明确非敏感错误码。
- 文件原子替换无法单独保证文件与系统密钥库跨资源事务。实现前明确各阶段故障矩阵；若要求覆盖凭据操作中途崩溃，使用非敏感操作意图记录和密钥库内暂存/备份凭据实现恢复，绝不将完整 Key 或恢复材料写入文件。不能将普通错误回滚描述为崩溃一致性保证。
- 新错误以稳定代码表达，同步桌面映射、四套翻译及核心测试，避免沿用对底层中文错误文本的匹配作为新增接口。
- 完整 Key 仅用于隐藏输入、短暂核心操作、凭据后端和剪贴板适配器；不进入列表、日志、终端输出、命令行参数或错误对象。

## 6. TUI 交互与平台适配

- 使用供应商列表、当前供应商 Key 列表、状态及快捷键栏；支持方向键、Tab、Enter、Escape、搜索、表单和删除确认。
- 供应商选择仅在当前会话保存，加载与删除后的回退行为对齐桌面；搜索和列表排序不写入设置。
- 后台执行持久化和网络任务，UI 仅接收非敏感摘要与错误码；覆盖加载、空状态、失败、重试及禁用状态。切换供应商后不得把旧任务结果显示到新目标。
- 四种语言为简中、繁中、英语和日语，系统语言解析规则与现有项目一致。TUI 使用独立 Rust 翻译资源，桌面继续 Vue I18n。
- 处理中文宽度、Unicode 编辑、小终端布局、粘贴与输入中的终端控制字符；隐藏 Key 字段，不回显完整值。
- 通过 RAII 终端守卫和 panic hook 恢复原始模式、光标及 alternate screen。强制结束无法运行析构，不承诺所有外部终止都能自动恢复终端。
- 复制按 Key ID 调用核心，由核心读取凭据并直接调用剪贴板接口，只返回完成状态。arboard 适配器启用并验证 Windows、Linux X11 / Wayland 所需支持，剪贴板实例在进程内保持存活；退出后的剪贴板保留行为按平台实测说明。
- Linux 密钥库不可用或锁定时报错，不回退明文。沿用现有凭据后端并验证实际平台配置，独立构建不要求 WebView，但运行仍要求桌面密钥库与剪贴板环境。

## 7. 实施顺序与验收

1. 合入 `upstream/main`，先运行 v1.1.0 基线检查，确认导航、排序和设置测试通过。
2. 建立 workspace 并提取核心，桌面适配保持协议与行为兼容；增加旧 JSON、设置默认值、凭据后端和共享目录测试。
3. 完成业务串行化、检测结果合并、原子保存、失败回滚及明确的中断恢复保证；使用模拟后端验证故障矩阵。
4. 两端接入启动锁，桌面延迟创建窗口；用独立进程测试竞争、正常释放、强制结束、崩溃、遗留文件及不可写目录。失败实例不能调用业务加载或恢复入口。
5. 实现 TUI、四种语言、隐藏输入、后台任务和剪贴板，验证中文输入、小终端与退出恢复。
6. 完成 Windows / Linux 构建、发布归档和三份开发文档；更新发布说明中的旧版本升级要求。

自动验证包括：

```text
npm run test:frontend
npm run build
cargo fmt --all -- --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo build -p key-switch-tui --release --locked
git diff --check
```

- 保留桌面现有 CI；增加 Windows x64 / Linux x64 的核心与 TUI 独立检查，显式 `-p` 选择包，避免 TUI 任务隐式构建 Tauri 或安装 WebView。
- 保留 `tests/navigation.test.mjs` 的选择、刷新、排序回滚、设置分类回归；增加协议、主题字段保留及检查期间编辑/排序的必要测试。
- 子进程锁测试覆盖桌面→TUI、TUI→桌面、各自多开和同时启动，确保只有一个获得锁；真实桌面窗口时序与原生提示另做平台验收。
- Windows 10 / 11、Linux X11 / Wayland 的凭据、剪贴板、中文输入和真实终端行为需要实测；CI 编译或模拟测试不能替代，未完成时明确记录验证缺口。

## 8. 发布与文档

- TUI Windows 发布 zip，Linux 发布 tar.gz，与桌面沿用同一应用版本和标签；新增包版本纳入现有版本一致性校验，不自行预定新版本号。
- 当前基线版本为 `1.1.0`，功能实际发布时同步项目既有版本位置、新 crate、根锁文件、WiX 和发布默认标签。
- TUI 附件上传到同一草稿 Release。先由统一步骤创建草稿，再由构建任务上传附件，避免多个任务竞态；保留现有标签触发、main 手动发布限制及 macOS 桌面产物。
- TUI 不生成自动更新清单，也不覆盖桌面安装包、签名或 updater 附件。
- 同步维护 `docs/development.md`、`docs/development.en.md`、`docs/development.zh-TW.md`，仅在实现完成后把实际行为写入开发文档；README 仅补用户入口和运行条件。
- 本文件是实施方案，不代表功能已经完成。提交、推送、打标签和发布按明确发布指令执行。
